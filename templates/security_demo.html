QUERY SECURITY

Unsafe vs Secure SQL

The project demonstrates the difference between directly concatenating user input and using parameterized queries.

✕ UNSAFE PATTERN
HIGH RISK

String Concatenation

query = "SELECT * FROM users WHERE username = '" + username + "'"
⚠️ Why is this dangerous?

Concatenating untrusted input into SQL can change the intended query structure.

✓ SECURE PATTERN
PROTECTED

Parameterized Query

cursor.execute(
    "SELECT id, username, password_hash FROM users WHERE username = %s",
    (username,)
)
🛡️ Why is this secure?

The database driver treats the supplied value as data rather than SQL syntax.
